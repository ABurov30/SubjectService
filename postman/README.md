# Postman — SubjectService

Импортировать [SubjectService.postman_collection.json](SubjectService.postman_collection.json) через Import в Postman. Переменные находятся в коллекции; отдельное окружение не требуется. Сервис и PostgreSQL должны быть запущены по [README](../README.md).

| Переменная | Назначение |
| --- | --- |
| `baseUrl` | По умолчанию `http://localhost:8080`, без завершающего слеша. Порт должен совпадать с `SUBJECT_PORT`. |
| `subjectName` | Имя нового Subject: непустая строка длиной до 255 символов. |
| `subjectId` | UUID из успешного ответа создания. |
| `subjectVersion` | Последняя версия из успешного ответа; используется для проверки повторного REVIEW. |

## Порядок запросов

Выполнить папку **Subjects** по порядку:

1. **Создать Subject** — `POST /subjects`, ответ 201, статус CREATED и версия 0. Перед запросом старые UUID и версия очищаются, после успешного ответа сохраняются новые.
2. **Отправить на рассмотрение** — `PATCH /subjects/status` с REVIEW. Ответ 200 подтверждает изменение Subject и регистрацию операции в одной транзакции.
3. **Повторить REVIEW без изменения версии** — проверяет сохранение статуса и версии Subject.
4. **Вернуть в CREATED** — меняет статус, сохраняя зарегистрированную операцию.
5. **Снова отправить на рассмотрение после CREATED** — возвращает REVIEW; прежняя операция Outbox сохраняется.
6. **Перевести в TERMINATED** — меняет статус, не отменяя прежнюю операцию Jira.

Повторный запуск папки создаёт новый Subject. Для ручного изменения существующего Subject задать `subjectId`; для проверки повторного REVIEW также задать его текущую `subjectVersion`.

Коллекция проверяет HTTP-ответы, UUID, статусы и неизменность версии при повторном REVIEW. Ответы API не содержат состояние Outbox или ключ Jira: наличие единственной записи и результат доставки проверяются в PostgreSQL, логах и интеграционных тестах. Успешный PATCH сам по себе не подтверждает создание Jira-задачи.

## Диагностика

Папка **Diagnostics** содержит health, проверку редиректа на Swagger и OpenAPI JSON с маршрутами создания и изменения статуса. В запросе редиректа выключено автоматическое следование перенаправлениям, чтобы проверить ответ 302. Папки Subjects и Diagnostics можно запускать в Collection Runner.

FAILED является конечным статусом Outbox; API ручного перезапуска отсутствует. Credentials Jira задаются в окружении сервиса и не передаются в Postman. Без доступной Jira REST-запросы сохраняют изменения, а фоновые попытки идут до настроенного лимита. Для проверки только REST можно запустить сервис с `OUTBOX_SCHEDULER_ENABLED=false`.

JSON использует [схему коллекции Postman v2.1](https://schema.getpostman.com/json/collection/v2.1.0/collection.json).
